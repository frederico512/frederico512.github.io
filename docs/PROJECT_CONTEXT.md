# Project context — Personal Website

This is the portable project brief. Share it with a new human collaborator or AI assistant when they need to understand the project quickly.

## Purpose

Build a personal website that starts as a simple, professional online home and can evolve into a portfolio. It should be useful now, easy to maintain, and flexible enough to grow as the owner's interests and projects develop.

## Owner and audience

- Owner: not yet specified in the website content. Do not infer or publish personal details.
- Audience: people who want to learn about the owner and see selected work.
- Primary goal: introduce the owner and provide a place to present projects and contact information.
- Secondary goals: practise web development, build good habits, and create a site that can be expanded over time.

## Owner's learning and tooling preferences

- Development computer: Windows 11.
- Editor: Visual Studio Code.
- Version control: Git for Windows; GitHub SSH authentication has been configured.
- Runtime installed: Node.js and npm, but this starter does not currently require either.
- Local preview: VS Code Live Server extension.
- AI coding tool: Codex desktop app is available. Other LLMs may also be used.
- Learning preference: work step by step, explain commands and decisions, and avoid installing tools without a clear reason.
- Priority learning topics: HTML, CSS, JavaScript, Node.js/npm when useful, browser debugging, Git, and later Arduino/electronics. Python is not a current priority.

## Technical baseline

- Type: static, single-page website.
- HTML: semantic HTML5.
- CSS: plain CSS with custom properties/design tokens; responsive layout.
- JavaScript: small vanilla ES module for progressive enhancement.
- Dependencies: none.
- Build system: none.
- Local server: Live Server; opening `index.html` directly is also possible.
- Backend/database: none.
- Forms/authentication/analytics: none.
- Deployment: not configured yet.

## Current page structure

- Header and primary navigation.
- Hero/introduction.
- About section.
- Projects section with three placeholder cards.
- Contact section with a placeholder email address.
- Footer with automatically updated year.

## Important constraints

1. Keep the first version deliberately simple. Do not add React, Vue, Angular, Next.js, Astro, Tailwind, Bootstrap, a bundler, or npm dependencies without discussing the reason and receiving approval.
2. Do not invent the owner's name, bio, skills, employment, projects, email, social handles, or other personal details.
3. Keep the website accessible, responsive, quick to load, and understandable to a beginner.
4. Explain meaningful changes and give exact Windows PowerShell commands when terminal steps are needed.
5. Use Git checkpoints for meaningful milestones, but never commit or push without the owner's request.
6. Update project documentation when the agreed structure or conventions change.

## Open questions — do not guess

- What name or brand should appear in the header and page title?
- What short biography should the About section use?
- Which real projects should be featured?
- Which contact method and social links should be public?
- What visual direction (colours, imagery, tone) does the owner prefer?
- What domain and hosting provider will be used?

## How to work on this project

Read `AGENTS.md` and `docs/DEVELOPMENT_GUIDE.md` first. Inspect the current files before editing. Work in small steps, explain the important choices, avoid unnecessary dependencies, and report changed files and checks performed. Treat this document as a factual snapshot; update it when the owner makes decisions.
